# Chronos migration review — data parity, schema usage, read-only guarantee

Date: 2026-09-09 · Server HEAD `85ecf30e` (dev) · Reviewer: read-only DB + schema-usage audit
Sides: **Phoenix dev budget DB** (legacy `public.*`) vs **Chronos serving DB** `transparenta_prod` (`budget.*`, `core.*`, `ins.*`, `search.*`, `flows.*`).

## Summary

1. **Schema usage is clean: no referenced table or column is missing in Chronos.** Every Kysely-typed column (kernel `types.ts`, budget, ins-native) and every raw-SQL column in the kernel repos and `src/app/native-*.ts` exists with a compatible type. The only schema drift is _omission_ (DB columns the types don't declare), notably `privacy_class` on `core.organization_identifiers`, `core.territories`, `search.documents`, `ins.*`; the raw SQL gates on it anyway.
2. **Lineage is the same snapshot for execution 2023–2025**: report counts per year × type match exactly on both sides (Chronos imported 2026-06-12 from the same source; Phoenix last import 2025-10-21 / 2026-01-25). Cluj-Napoca 2024, county population (19,053,815), dimension labels, and commitments 2023/2024 sums match to the cent.
3. **One confirmed money bug (P1)**: Chronos flags `is_yearly` per (entity, year, report_type, main_creditor, sector) scope, so an entity that switched main creditor mid-year carries **two** yearly rows; the annual MV keeps both, and the server sums across creditors (`budget-repo.ts:1027-1030`). Entity 26429279 reports 2024 detailed expense **2.92 bn instead of 2.05 bn** (+869,074,554.38, equal to the MV delta to the cent). 2023 and 2025 carry the same pattern (115 / 53 scopes).
4. **Commitments**: the eight available-credit columns exist and are populated (`ytd_*` on every row; the `latest` forms only on `is_yearly` rows, by design). Phoenix dev's 2025 commitments MV is stale (its own base rows say 868.1 bn paid, its MV says 767.9 bn) and Phoenix lacks Dec-2025 commitment lines; Chronos is ahead. Candidate staging T180000 is not served.
5. **Read-only guarantee holds for the serving DB**: chronos-dev runs `dist/redesign-api.js`. The only read-only role with live sessions is `transparenta_prod_phoenix_dev_readonly` (13 idle, member of `pg_read_all_data`, `default_transaction_read_only=on`, `statement_timeout=15s`); that is consistent with the chronos-dev pool but the exact role is not verifiable without reading the secret. Every candidate read-only role has `default_transaction_read_only=on`, so the guarantee holds regardless. No write builder targets the prod pool. Writes go only to the chronos-dev user database. Factor set 2 is promoted and its digest equals the code pin; the embedded 2025 FX 5.05 / GDP 1.88e12 constants are only reachable on the legacy compatibility path.
