## Summary

1. **Factor set:** which factors a root uses is decided by the _entrypoint_, not the root. On Chronos dev (`dist/redesign-api.js`, modules = defaults + `ins-native`) every money path on `/api/v1/graphql`, `/api/v1/mcp` and the native map routes uses **promoted set 2** (digest `5f2948ec…`, `promoted_at` 2026-09-08, run 23230) through `makeNativeBudgetFactors`; set 1 is wired only as an unreachable fallback and doc 13 §9 ("executionAnalytics pinned to set 1") is stale for that deployment. On the Phoenix `api.js` embedding (`REDESIGN_SURFACE_ENABLED='true'` in `k8s/base/configmap.yaml`, `PROD_DATABASE_URL` present in the dev and prod overlays) the same endpoint serves **three sources at once**: unpromoted set 1 (carry-forward) for `executionAnalytics`, set 1 strict for `entityAnalytics`/`aggregatedLineItems`, and the **embedded JS-float table** (2025 EUR 5.05, GDP 1.88 T, 2026 estimates) for `entityRankings`/heatmaps/timeseries/line items and the budget MCP tools. Runtime mount on Phoenix is unverified (config-level confirmed).
2. Set 1 vs set 2 differ in every GDP year 2010–2024, every `population_ro` year, 2025 EUR (5.0245 vs 5.0415) and 2025 USD (4.6225 vs 4.4705); set 1 has no CPI/GDP 2025. Embedded 2025 EUR 5.05 / GDP 1.88 T still have a live reader on the Phoenix embedding via `budget-repo.ts` → `money-factor.ts:78-84,104` → `analytics.ts:24-83` (JS `1 / 5.05` bound as `numeric`).
3. **Population:** the four native readers are consistent (exact-year POP107D + admitted sector rows, division before sum, fail-closed), but the admission pins are hard-coded in `src/app/native-map-population.ts` / `native-sector-population.ts`, the sector admission is re-validated on _every_ population read, and a drift fails **nominal** entity rankings and the nominal entity table too, not only per-capita. Acceptable for dev, not for prod without a DB-side admission pointer.
4. **Maps:** 20 native REST routes mount without prefix; money leaves as decimal text; `is_territorial_executive` is now carried on advanced-map (doc gap closed) but the legacy `mcp` module still strips it silently. The native mount puts `makeAuthMiddleware` on the three public GETs (stale token → 401/503 where legacy bypassed), rate-limits all 20 routes at 30/min per IP, and drops the legacy cache.
5. **Reference/kernel:** the `entities`/`uats` legacy roots are **not ported** (no `LegacyEntity`, no PageInfo clone in `src/`), so the §2/§3 collision and SDL-parity questions are N/A. The kernel imports no source module but hard-codes Bucharest sector/county semantics in two `shared/` files. `core.public_entities` has no `privacy_class` column (DB confirmed), so the ungated name reads there are a P3 residual, not a leak.
