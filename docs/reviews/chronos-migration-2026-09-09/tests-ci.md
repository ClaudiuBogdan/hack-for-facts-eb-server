- **Timers, network, dates.** `vi.useFakeTimers` in 11 files; `Date.now()`/`new Date()` in 31 test files (T-23). No unit/integration test hits a real network URL (the transparenta hostnames appear only in config-validation strings). The GM specs are network by design.
- **Timeouts.** `vitest.config.ts`: no `testTimeout` (default 5 s), no pool/worker settings, `globals: true`, setup only sets env. `vitest.gm.config.ts`: 30 s test / 60 s hook, sequential, `globalSetup` writes the cutover summary. `vitest.e2e.config.ts`: 30 s / 60 s, sequential, Docker probe in `setup.ts` with a 60 s hook. The "five-second cold-bootstrap timeout" in the 09-05 docs is the default 5 s cap on app-bootstrapping tests; the documented repeat offender is `eslint-boundaries.test.ts` (T-12).
- **Determinism aids in the new code.** `makeTestClock` injected in user-data contracts; `TEST_GM_RUN_ID` single-use directories; migration SHA pinning in the e2e suites; lossless number parsing in the GM client. These are good.
