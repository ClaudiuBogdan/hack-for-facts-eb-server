# Chronos migration review: composition, infra, deployment

Reviewed at `dev` HEAD `85ecf30e` on 2026-09-09. Read-only; live cluster facts from `kubectl` (names, images, env var names only).

## Summary

1. The Chronos dev pod runs `dist/redesign-api.js` (kernel-only), not `dist/api.js`; live image `08a7fb6b…` matches the overlay pin at HEAD and Argo is synced to `85ecf30e`. No drift.
2. The Chronos dev pod does not read Phoenix: its secret carries only `PROD_DATABASE_URL` + five `CLERK_*` keys, default-deny egress allows only Chronos prod Postgres/Meili/OpenSearch and the dev user DB, and the `redesign-api.ts` import graph never touches `initDatabases`, `build-app.ts` or `ins-interim-surface.ts`. The reverse is true: Phoenix dev (auto-synced from the same `dev` branch) reads Chronos through `REDESIGN_SURFACE_ENABLED=true`.
3. Two P1s: liveness/startup probes time out at 3 s while the kernel health probe is bounded at 4 s per dependency (restart under aux hang or pool saturation); and `k8s/base/*` is not frozen for Phoenix dev because that Argo app still auto-syncs with prune + selfHeal from `dev`.
4. `src/app/native-*.ts` holds source-manifest pins, SHA-verified admission logic, decimal/BigInt math and raw SQL; the ESLint `boundaries` element for `app` is only `src/app.ts`/`src/api.ts`, so nothing under `src/app/` is checked, which is why module internals are imported there.
5. CI pins images by committing to `dev` without fetch/rebase; with `cancel-in-progress`, developer pushes race it (15 "Merge remote-tracking" commits, 13 since 2026-09-06), pinned trees are never CI-validated, e2e tests never run in CI, and the golden-master run targets the frozen Phoenix dev image.

## Infra assessment

- `ad4fdaeb` (borrowed transactions): correct. `Kysely#isTransaction` is the right primitive; `Transaction<DB>` is assignable to `Kysely<DB>`, so `UserDbConnection = UserDbClient` is sound; `inTransaction` reuses the outer transaction so rollback and deferred invalidation stay with the owner. Caveat (pre-existing): `forUpdate` is silently dropped when a non-transaction client is passed (`learning-progress-repo.ts:735`). Covered by `tests/e2e/user-transaction-ownership.test.ts`, which CI does not run (F11).
- Pool sizing (`80944f21`): dev 10 / prod 25 per replica on `PROD_DB_POOL_MAX`; the chronos-dev overlay sets 10 with `maxSurge: 0`, so ≤ 20. Kernel pool: `min 4`, `connectionTimeoutMillis 10 s`, `idleTimeoutMillis 30 s`, `statement_timeout 15 s`, per-pool type parsers (`pool.ts:107-124`); pg-pool 3.14 supports `min`. User pool: `max 3`, `statement_timeout 30 s`, CA-verified TLS with SNI check (`user-client.ts:36-47`) against CNPG `max_connections 40`.
- Pool error handling: kernel and user pools register both `pool.on('error')` and per-client `error` listeners; legacy pools do not (F9).
- Config: `redesign-env.ts` validates with TypeBox and fails fast; `Value.Clean` drops unknown keys; auth/user-data groups are all-or-nothing. `PROD_DB_SSL` is unset on Chronos so SSL derives from the URL's `sslmode` (`pool.ts:92-101`); unverified which mode the sealed URL carries.
- Schema: startup only probes `userdataanonymizationaudit` (`build-redesign-app.ts:349`); no DDL runs from the server. Read-only rule over `transparenta_prod` holds (only `kernel.db` is passed to source modules; writes go to the user DB via `advanced-map-*` and the anonymizer).
