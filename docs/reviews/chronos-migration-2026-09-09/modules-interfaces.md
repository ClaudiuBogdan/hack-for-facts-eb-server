# Chronos migration review — source modules, kernel interfaces, MCP, auth, GraphQL hygiene

Scope: every change since `b4e0ec38` (2026-08-24) to `legal`, `companies`, `parliament`, `procurement`, the kernel MCP/GraphQL shells, `mcp`, `auth`, `clerk-webhooks`, `entity`, `uat`, `datasets`, `health`, `infra/graphql`, `common`, `widgets`, plus a contract sweep of every source module against `docs/server-redesign/00-foundation-shared-kernel.md`. Read-only review at HEAD `85ecf30e` (branch `dev`), 2026-09-09. No database reads were made; every privacy finding is therefore "gate absent in code, data impact unverified", and each names the one `db-read` count that would settle it. Findings marked "sub-review" came from three parallel reviewers and were spot-checked where stated.

## Summary (5 lines)

1. **Interfaces:** all ten redesign source modules follow `core/{ports,types,usecases}` + `shell/{repo,graphql,mcp}` and export `makeXModule(deps)`; every MCP tool is annotated `readOnlyHint` by the kernel. The gaps are structural, not per-commit: REST exists for only three modules (pnrr full, parliament 1 route, legal 2 routes), no redesign route is in any OpenAPI, procurement registers no `SourceContributor`, and `legal/mo/` is a third layout outside both `core/`/`shell/` and the ESLint boundary patterns.
2. **Privacy (highest priority):** `legal.document_nodes` is read with no `privacy_class` predicate on the outline and `get_legal_node` paths (M01); the companies repo reads `core.organizations` at 12 sites with no `privacy_class` pin while the kernel pins all 7 of its own (M02); render chunk N never re-checks `privacy_class` (M07); `core.territories.privacy_class` is untyped and unpinned in 5 of 6 kernel reads (M18). All are latent by the commit messages' own measurements; none is verified against data here.
3. **Security:** the anonymous `/api/v1/mcp` rate limit is keyed on `request.ip`, and both entrypoints run Fastify with `trustProxy: true` (`api.ts:169` defaults to it when `TRUST_PROXY` is unset, which it is in every manifest), so the key is the leftmost `X-Forwarded-For` entry, which the client controls: the limit is bypassable by rotating the header (M03). The legal render route sets `s-maxage=86400` + SWR on a URL that carries no generation, so a shared cache can keep serving a document after a public→restricted flip (M04).
4. **Correctness regressions found in the reviewed commits:** the search degrade path is honest in code but its LLM-facing text still claims an exact-CUI lookup that no longer exists (M08); `servableDocumentRowSql` now references a column the Kysely type and the e2e DDL do not declare (M05); the procurement "build 8" gate is a compile-time constant that cannot notice the next data build (M06); `retrieval-repo` re-introduces the ordering tie that 75409f0b fixed two lines above (M15); `ParliamentMemberVote.billKey` was not migrated to the vote-resolution contract (M20).
5. **GraphQL hygiene:** the merged `/api/v1/graphql` schema builds cleanly at HEAD (171 Query roots, 907 types, 6 `@deprecated` fields, no Mutation) but no CI test stitches the full module set and there is no SDL snapshot (M12); the merge gate misses cross-module `extend type` on module-owned types (M13); the unified and standalone entrypoints serve different INS roots on the same path (M09). Doc-13 renames (`budgetSectorCatalog`, `LegacyEntity`, `extend type PageInfo`) are in place.
